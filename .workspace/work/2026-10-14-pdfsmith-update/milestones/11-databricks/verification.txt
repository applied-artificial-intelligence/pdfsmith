Databricks SDK contract verification - October 15, 2026

before.json uses the inherited installed adapter with actual Databricks SDK
0.116.0 and a strict offline requests adapter. A normal documented nested document
and page-level errors both returned empty strings; pending statements failed
immediately, an empty result was called success and malformed JSON was returned
as parsed text. The outgoing old SQL is retained and marked legacy_sql. Its
string/base64 signature disagrees with the current binary/options-map docs;
no SQL engine was called to claim empirical SQL rejection. before-source.tar.gz
preserves the original adapter and reproduction.tar.gz preserves the diagnostic.

The replacement constructor validates options and binds explicit host/warehouse
configuration without SDK import, credentials or warehouse discovery. Missing
inputs fail first. Inline PDFs are limited to 10,000,000 bytes and 500 pages;
pypdf is a declared dependency. Larger documents need a separate staging design.
SQL uses unbase64 over the actual input, an explicit schema version 2.0 options
map, disabled figure descriptions and to_json over the VARIANT result. Figure
and image generation/persistence are excluded. Table HTML remains HTML in text.
The SQL string cannot establish server-side acceptance without a workspace run.

Actual SDK resource methods serialize one statement submission, bounded pending
polls and chunk retrieval. Success requires SUCCEEDED plus an untruncated
one-row, one-column JSON_ARRAY manifest, complete chunk coverage, one JSON object,
empty error_status, confirmed schema version, complete ordered pages and elements.
Missing first chunks are fetched through the SDK chunk endpoint. Failed SQL,
missing/malformed JSON or partial document metadata never becomes empty success.
Blank elements with complete successful page metadata return an empty string.

The wrapper owns one client per parse, disables async token refresh, and supports
PAT or OAuth M2M credentials at parse-time client creation. SDK 0.116.0 obtains
workspace metadata during client creation; this discovery/authentication happens
before the statement deadline, not inside the bounded statement polling period.
A diagnostic using the synthetic offline.invalid host encountered the SDK's long
metadata retry and was stopped with SIGINT; it did not call a provider. All final
verification intercepts that actual SDK metadata HTTP request as well as SQL.

The SDK has no no-retry configuration and no public session close. An owned SDK
clock rejects retry/backoff before a replay, preserving the original SDK error as
cause; the owned underlying session is closed explicitly. The SDK range is narrow
because these seams must be revalidated on upgrade. The actual 500-response check
asserts exactly one submission. No automatic replay follows ambiguous submission.
Known statements get bounded best-effort cancellation plus one status check.
Cancellation acknowledgement alone is not termination; resource IDs and uncertain
completion remain visible. Completed output survives session-close failure in
BackendOperationError and a separate private CLI recovery JSON.
