Parser feature guide
PARSER_GUIDE.md is part of the merged source and linked from README.md:
https://github.com/applied-artificial-intelligence/pdfsmith/blob/9b6ecb298581ed910ccfd010989c0dcffb9ad8e9/PARSER_GUIDE.md
It covers all 19 registered adapters with 30 official source URLs, comparing OCR,
tables, reading order, geometry, output forms, configuration and operating needs.
It distinguishes documented upstream features from the PDFsmith subset and actual
execution evidence. It is a feature/selection explanation, not a new benchmark,
independent feature verification or a universal quality ranking. Its documentation
research date is October 16; upstream features can exceed the tested versions.

Actual local E2E evidence covers pypdf, pdfplumber, PyMuPDF, PyMuPDF4LLM, PDFMiner,
PDFium, Kreuzberg, Extractous, Unstructured, Docling and Marker. The owning
milestones identify tested versions, public/controlled inputs, options and routes,
source/wheel/dependency hashes and outputs. All tested Python versions are within
3.10-3.13; Unstructured requires 3.11-3.13. Model/native prerequisites still apply.
These runs establish the recorded execution capability, not comparative accuracy,
OCR quality, reading-order correctness on every document, speed or a best parser.

All eight hosted adapters have four-Python real-SDK offline contract evidence.
After explicit USD 5 authorization, five passed actual API/CLI processing of the
approved public eight-page and controlled two-page PDFs on Python 3.12: AWS,
Azure Read, Google Document AI, LlamaParse Fast and Anthropic. OpenAI and Gemini
passed model-access checks but generation was blocked by exhausted prepaid
balances. On October 16 Stefan declined further funding and waived the remaining
two live checks, accepting documentation and existing SDK offline evidence. The
engineering/verification scope is closed with these declared limits. Databricks
was explicitly excluded and received no calls. These facts do not establish all
modes/models, OCR quality or comparative results.

LlamaParse uses llama-cloud 2.18.x; the live check used Fast/2026-06-15. A live
422 exposed an invalid zero failure ratio and unsupported tier/version pairing;
both were repaired with producing regressions before the successful check.
LlamaParse retains explicit tier and published version,
disable_cache=true by default and complete ordered page checks. Requested
settings and response echoes do not confirm runtime version or cache hits.
LlamaIndex ParseBench is external evaluation work, not a PDFsmith result.
Databricks SQL compatibility is documentation-backed plus SDK offline evidence,
not validation by a live warehouse engine. Usage fields on the LLM wrappers
retain reported counts; monetary fields are unknown, with no old-price estimates.

All adapters are PDF-only. Controlled scanned-PDF OCR was exercised on selected
local modes, as recorded in the matrix. Registration/dependency presence does not
mean configured or operational. Discovery does not load models or credentials.
Automatic selection retains a fixed local preference order and never chooses a
hosted service. Output can be plain text or backend-produced Markdown; the
pdfplumber wrapper does not separately convert tables to Markdown.

Marker 2.0/Surya 0.22.1 uses owned local inference processes. Public text-PDF
checks used text-layer mode; controlled scanned OCR used its default mode. It
requires a compatible llama.cpp binary and model assets, and an environment
separate from Unstructured/all and current Anthropic/OpenAI/frontier extras.
Unstructured needs preinstalled loadable spaCy 3.8.0 assets and rejects a damaged
installation before the SDK's implicit repair/download fallback.

Supported source examples
The merged README is the authoritative installation/API/CLI reference:
https://github.com/applied-artificial-intelligence/pdfsmith/blob/9b6ecb298581ed910ccfd010989c0dcffb9ad8e9/README.md
Its documented checkout installation selects .[pypdf,pdfplumber]. The actual
installed-source README example is recorded in milestones/16-final/readme-example.json;
the unchanged local API/CLI behavior also has installed and regression evidence.
Examples that may be quoted with the merged-source qualification:
  from pdfsmith import parse
  text = parse("document.pdf", backend="pypdf",
               backend_options={"extraction_mode": "layout"})
  text = parse("document.pdf", backend="pdfplumber")
  pdfsmith parse document.pdf -b pypdf
  pdfsmith backends --all
The two console lines are separate CLI examples, not Python statements. The PDF
must exist and the selected extra must be installed. Do not pair these examples
or the 0.3.0 contract with an unqualified install of the released PyPI 0.2.0 wheel.
